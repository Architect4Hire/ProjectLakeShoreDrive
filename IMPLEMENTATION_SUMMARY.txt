## KEY FEATURES

✅ Captures: MessageId, CorrelationId, CausationId, EventType/Version, Consumer, Producer,
            OccurredAt, ReceivedAt, DeadLetteredAt, AttemptCount, Reason, Description,
            BusinessKey, TriageStatus, Notes, ReviewedBy/At

✅ Triage Workflow: Unreviewed → Diagnosis → EligibleForReplay|IneligibleForReplay → Resolved

✅ Guidance Heuristics:
    - Attempt count ≥10 → likely systemic issue
    - Deserialization/schema → likely permanent
    - Authorization/permission → likely permanent  
    - Not found → likely permanent
    - Timeout/network → likely transient
    - Age >24 hours → warn about state drift

✅ Domain Ownership: Records owned by calling domain's DbContext (no cross-domain sharing)

✅ Idempotent Recording: Duplicate message IDs safely ignored

✅ Concurrency-Safe: RowVersion prevents silent overwrite of concurrent triage updates

✅ No Auto-Replay: System provides eligibility guidance; operators make explicit decisions

## ARCHITECTURAL ALIGNMENT
