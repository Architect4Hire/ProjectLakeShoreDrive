# Project Lake Shore Drive — Document Generation Design

## Principle

Documents are composed from approved structured engagement data and reusable sections. They are not generated by sending the entire engagement to one uncontrolled prompt.

## Supported artifacts

MVP target:

- Executive Summary
- Proposal
- Statement of Work
- Architecture Vision
- Architecture Assessment
- Project Plan
- RAID summary/log
- Requirements Matrix narrative
- ADR starter set
- SCRUB implementation prompts
- README / repository bootstrap
- Project Kickoff Package

## Document model

```text
Document
├── metadata / type / version / status
└── ordered DocumentSection(s)
    ├── content
    ├── provenance
    ├── citations
    ├── generation history
    ├── approval status
    └── lock state
```

## Section generation

Each generation operation explicitly defines:

1. requested section;
2. task/prompt version;
3. approved engagement facts;
4. approved requirements;
5. selected patterns/ADRs/RAID/estimates;
6. approved template content;
7. explicitly selected historical sources;
8. required output shape/audience.

Regeneration of one section never overwrites approved unrelated sections.

## Section state

```text
AI Draft
→ Architect Edited
→ In Review
→ Approved
→ Published
→ Superseded
```

## Provenance

A section can distinguish:

- current engagement structured facts;
- template content;
- pattern library;
- historical retrieval;
- user-authored text;
- AI inference/transformation.

Historical claims must have resolvable citations.

## Review behavior

The workbench supports:

- edit;
- generate/regenerate;
- shorten/expand;
- change audience;
- inspect sources;
- compare versions;
- accept/reject changes;
- approve;
- lock.

## Package workflow

A package is a durable workflow that fans out section/document work where parallelism is safe, waits for required dependencies, records failures, and can pause for human review.

## Export

Approved content may export to Markdown first, followed by Word/PDF and tabular formats as required.

Export uses the exact approved artifact versions effective at export time.
